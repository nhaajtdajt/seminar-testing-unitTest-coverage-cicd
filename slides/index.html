Unit Test

Test nhanh, độc lập, lặp lại được

  • Test mock quá mức có thể xác nhận lại điều đã stub.

CC-3: gate phải chặn được bản thiếu test

# Kỳ vọng: exit 1, vì 50% < 90%

  • Khôi phục bộ test đầy đủ: build pass.
  • GitHub Actions đã chạy gate thật; PR đỏ bị chặn và PR xanh được phép merge.

Code Coverage

100% branch vẫn có thể kiểm sai rất ít

  • Test bẫy đi đủ nhánh nhưng bỏ assertion tiền ở ca hợp lệ.
  • JaCoCo: cả bộ yếu và bộ đầy đủ đều phủ 100% branch.
  • PIT: bộ yếu diệt 3/11 mutation; bộ đầy đủ diệt 10/11.
  • Mutant còn sống ở bộ đầy đủ tương đương theo đặc tả ngưỡng trả 0.

CI/CD

CI, Continuous Delivery, Continuous Deployment

Commit → Build + Test → Artifact → Duyệt → Triển khai
        |______ CI ______|
        |________ Continuous Delivery ________|
        |_______________ Continuous Deployment ___________|
  • CI (tích hợp liên tục): mỗi lần đẩy code, tự build và chạy test; lỗi phát hiện ngay.
  • Continuous Delivery: sau CI luôn có bản (artifact) sẵn sàng phát hành; việc triển khai do người bấm duyệt.
  • Continuous Deployment: bản đạt mọi kiểm tra tự động được triển khai lên môi trường chạy thật, không cần người duyệt.
  • Mỗi mức đòi hỏi bộ test và gate tin cậy hơn mức trước.

CI/CD

Nhóm làm đến mức nào?

  • CI: có. Mỗi pull request tự chạy test và coverage gate trên GitHub Actions.
  • Delivery: ở mức tạo JAR (job package) và lưu làm artifact; chưa có bước duyệt phát hành.
  • Deployment: không làm. Chủ đề là kiểm thử nên không triển khai lên máy chủ.
  • Nếu cần: thêm job deploy chạy sau package, có điều kiện nhánh master và bước duyệt.

CI/CD

Từ lệnh tại máy đến pipeline

test [JDK 25]
        ↓
coverage-gate [branch >= 90%]
        ↓
package [JAR + artifact]
  • CI kiểm thay đổi được tích hợp thường xuyên.
  • Bản hiện tại dừng ở kiểm thử/đóng gói; chưa tự deploy ứng dụng.

CI/CD

CI-1/2/3: workflow và minh chứng

  • CI-1: checkout, setup JDK 25, chạy Maven. CI-2: cache dependency, upload báo cáo, step summary.
  • CI-3: ba job nối bằng needs; chạy khi có pull request, push vào master/seminar-core, hoặc chạy tay.
  • Đã chạy thật trên GitHub: PR #1 xanh; PR #2 đỏ vì coverage-gate (branch 0,00 < 0,90) rồi xanh lại.
  • Required checks bật trên master: PR đỏ #6 có trạng thái BLOCKED, không merge được.

CI/CD

GitHub Actions: cấu trúc workflow

  • Workflow viết bằng YAML trong .github/workflows, chạy trên runner do GitHub cấp.
  • Ba job nối nhau bằng needs: test → coverage-gate → package.
  • Job trước đỏ thì job sau không chạy.
  • Cache Maven và artifact giúp chạy nhanh và lưu báo cáo.

CI/CD

Khi test xanh mà vẫn bị chặn

  • Xóa FineCalculatorTest: job test vẫn xanh (không test nào fail).
  • Job coverage-gate đỏ: FineCalculator phủ 0,00 nhánh, yêu cầu 0,90.
  • Job package bị bỏ qua vì needs: code thiếu test không được đóng gói.
  • Test pass chưa đủ; cần gate về coverage và PIT cho chất lượng assertion.

CI/CD

CI gặp vấn đề: điểm yếu quan sát được

  • Đổi pom.xml (dù chỉ một dòng comment) làm khóa cache đổi: log ghi maven cache is not found.
  • coverage-gate chạy lại toàn bộ test; thời gian runner dao động (cùng bước: 29 s đến 70 s).
  • Required check làm PR kẹt nếu workflow trên master chưa có trigger (PR #4).
  • Gate chỉ kiểm cái được cấu hình; chưa đo được lộ secret hay flaky test.
